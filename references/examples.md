# 阅读与备考完整示例

以下是自编教材的教学示例，不是用户真实成绩或每次都相同的模型输出。材料与脚本流程对应 `tests/test_skill.py` 和 `tests/demo_workflows.py`，可运行后查看实际 JSON 结果。话术用于说明体验；正式使用时读取用户自己的材料、生成新题和真实来源位置，不照抄这里的书名、结论或成绩。

## 阅读：从讲清概念，到检查自己的理解

**1. 用户提出目标**

用户：“陪我精读《有效反馈与检验理解》，文件在我提供的路径里。我不考试，读完第一章考考我，也帮我记住进度。”

伴读：“按阅读模式来。我会先读第一章，解释概念，再用少量问题检验理解。进度保存在你指定的本地学习目录。”

**2. 阅读与解释**

第一章原文：“反馈的目的是帮助改进行动，而不是要求接受者无条件服从。”

伴读：“有效反馈要指出可观察的行为与可调整的行动。例如‘这次交付晚了一天，下次发现风险请提前告诉我’，能让对方知道怎么改。‘你就是不认真’只给了评价。”

来源：第一章《有效反馈》，实际索引中的 `c0001`、`chunk_id=0`。正式回答应使用本次工具返回的定位。

**3. 先出题，等待作答**

伴读：
1. 判断：有效反馈的目的，是让接受者无条件服从。请说明理由。
2. 判断：只说“你很聪明”，未必构成有效反馈。请说明理由。
3. 用自己的话解释“反馈具体行为”与“评价固定能力”的区别。
4. 你是否认同“反馈需要及时”？举出支持或反对的场景，说明条件。

此时不展示答案或解析。

**4. 作答与有依据的反馈**

用户：“第一题错，反馈是为了改进行动。第二题对。第三题，前者能告诉人怎么调整，后者只给标签。第四题，情绪激动时可以稍后沟通，只要仍然具体、可执行。”

伴读：“第一题和第三题抓住了目的与对象。第二题判断正确，但还缺理由，先记为‘待补充解释’：仅说聪明，没有指出哪种行为值得保留或如何改善。第四题的异议有具体条件，可以成立；理解作者观点不要求无条件赞同。”

阅读模式不给考试总分，也不凭这一次回答宣布长期掌握。

**5. 保存和下次续学**

伴读：“已记录第一章读过；‘具体反馈’仍需补充解释。下次可先用一句话说明第二题的理由，再读第二章。”

用户下次说：“继续上次学习。”

伴读先读取真实本地记录，确认同一书籍与阅读模式，再接续；多个记录有歧义时让用户选择。

## 备考：做错之后，回到原文，再换题验证

**1. 确认范围**

用户：“用这份教材陪我备考，先练第一章，把错题留下来。”

伴读：“先围绕第一章生成章节练习。你还没提供官方大纲，以下是教材练习，不称为官方题或预测题。”

**2. 章节练习**

伴读：“哪项最符合有效反馈？A. 你就是不擅长这个；B. 指出可观察行为及改善方式。”

用户：“A。”

**3. 评分、错因、依据**

伴读：“本次 1 道客观题，答对 0 道，得分 0%。正确答案 B。A 把问题归于固定能力，无法指导改进行动。原文依据：‘反馈的目的是帮助改进行动，而不是要求接受者无条件服从。’已把‘反馈目的’记为待复习考点。”

这里的分数只描述本次练习，不代表考试能力。答案与计分由脚本核对；解释依据实际原文。

**4. 新情境复测**

伴读：“同事交付延迟时，哪种反馈更符合本章？A. 你总是这么差；B. 这次比约定晚了一天，请先确认风险并及时通知。”

用户：“B，因为它描述具体行为，还提出了调整行动。”

伴读：“这次新情境题回答正确，理由也对应同一考点。已记录本次复测通过，并解除原题的待复习标记。以后再次答错时，仍可重新进入复习。”

**5. 续学结果**

读取备考状态后显示已完成的练习与尚未解决的错题。阅读模式里‘第二题缺理由’的记录仍单独保留，不被备考的通过结果覆盖。

## 如何复现脚本结果

```bash
python3 tests/demo_workflows.py
```

成功输出包含 `status=pass`、`cli_calls=17` 和逐次 `operations`。脚本验证了先隐藏答案、阅读判断理由不足保留为 partial、客观题计分、错题登记与新题复测、两种模式记录隔离。开放题评议字段在这份演练中为预设样例输入。
